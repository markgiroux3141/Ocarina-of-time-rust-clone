# The decomp name map

The names of decomp commit `2f4c25d` paired with those of zeldaret/oot main at `52a510f`
(both gc-eu-mq-dbg), for the upgrade in [ADR 0031](../adr/0031-decomp-main.md). It holds names
and addresses only, no game data.

| File | What it is |
|---|---|
| `name_map.tsv` | Every name that changed, 36,304 rows, generated by `scripts/name_map.py build` (don't edit) |
| `unpaired.tsv` | The old names with no partner, and the one pairing with two candidates, generated with it |
| `manual.tsv` | 162 successors checked by hand, for what the generator can't pair (macros, anonymous enums, types whose fields changed too), each with its evidence. `build` reads it |

Look a name up either way with `python scripts/name_map.py find NAME`. Regenerate the files
with `scripts\run\name-map.bat` (both decomps built in Docker), then review `git diff
docs/name-map`.

## How the rows pair

| Kind | Rows | Paired by |
|---|---|---|
| `func` | 2,012 | address, in the two builds' ELFs (`.symtab`, and the `.mdebug` that holds IDO's statics) |
| `data` | 30,248 | address: globals, `D_` and `s` statics, and the assets' symbols per output section (the ROM file) |
| `field` | 1,269 | offset, from the `/* 0xNN */` comments, nested structs flattened; scope is the struct |
| `enum` | 2,422 | value, within the renamed or kept enum type; the table-generated enums (`NA_BGM`, the actor and object ids) by row |
| `define` | 171 | family prefix and value, in the headers the old one's contents moved to |
| `struct`, `enum-type` | 50, 32 | name, file and members |
| `file` | 100 | the symbols they define (a split file lists its successors) |

A name renamed in one file but kept in another (`sTunicColors`) also gets a row to itself, so
the migration only renames it where the file is known.

## The review

`unpaired.tsv` has 640 rows:
- 387 data symbols with no symbol at their address on main: 72 in `boot` (libultra's local
  labels: `ai`, `pi`, `sp`, `panic`...), assets that main's XMLs no longer name or name at
  another offset (37 in `gameplay_keep`, 13 in the test room `sasatest_room_0`), and labels in
  `code`;
- 152 `#define`s main dropped or turned into enums or expressions (`DPM_UNK` became a literal 0);
- 22 fields of structs whose layout changed, 16 structs and 30 enum types that main removed or
  merged, 23 files that were split or emptied, 9 enum members, 1 function (`makerom`'s
  `entrypoint`);
- 1 ambiguous pairing: `D_800093F0`, at both `cic6105TextStart` and `rspbootTextEnd`. Nothing
  cites it.

Checked against the repo after the migration, 21 of the unpaired names still appear in it. 20
are English words or Rust names that share a spelling with a libultra label (`counter`, `cart`,
`backwards`, `height`, `data`...). The one real citation, `struct_80034A14_arg1` in
`oot_game::npc`, is main's `NpcInteractInfo`, fixed by hand with its field names.

The migration's own leftovers were checked the same way:
- A field citation whose struct the migration couldn't tell from the line or the file (an
  `unk_08` in a comment, with eight structs having one) was left as it was, then reviewed by
  hand. Most are `PlayerAgeProperties`' `unk_24`, `unk_28`, `unk_2C`, `unk_30`, `unk_34` and
  `unk_94`, which main still calls that. The rest were renamed when main's struct names them
  (`NpcInteractInfo.headRot`, `CutsceneContext.timer`, `ItemChangeInfo.changeFrame`...).
- The names main removed (`Audio_SeqCmdB`, `CsCmdBase`, `WATERBOX_BGCAM_INDEX`,
  `gTatumsPerBeat`, `z64elf_message.h`'s `ELF_MSG_*`, `<Name>_InitVars`) were rewritten by hand
  to what main has in their place.
- 214 renamed `unk_` names that several structs share were listed with the struct each rename
  took, and checked against main's headers. One was wrong (`oot_game::npc::NpcTrack`'s comments
  had taken `NpcTrackingRotLimits`' names) and is fixed.
